# 31AO: one complete desktop schema and C-parser check

31AN's owner-run observation succeeded but hid the four unknown tag names and
could not qualify `love` or the LAB expression. REA of the generic formatter
now supplies a finite catalog and exact types. This tool checks the whole
desktop output against the proposed **real C parser**, privately, before any
new Recovery visit. It does not perform Recovery admission.

Default/help is inert. An owner-run live check from this checkout is:

```bash
sudo /usr/bin/python3 -I tools/policy31ao/probe.py --live
```

Keep authentication in Terminal. Return only its finite JSON; never raw
`bputil` text/JSON. The M5-reviewed syntax checker must already exist at its
fixed workspace path with the exact hash pinned by `probe.py`. Missing or
different compiler output refuses. No download or compilation occurs live.

The wrapper hash-verifies its own scanner, ACL guard and old 31AN runtime,
which retains the frozen 111-source target/stager closure. It requires root on
Darwin, the exact target model, current Original, distinct lab/Original/Data
roles and original container/internal guards. Private identities remain in
memory. Fresh target observation after all reads must match the first binding.

For LAB and ORIGINAL it makes one bounded text display and one display-only
JSON request, each bounded to 20 seconds/65,536 stdout bytes by the frozen
capture implementation. Private stderr is discarded. Each text capture also
passes over stdin to the original desktop syntax executable. Neither policies
nor parsed values are written to files, command arguments or public output.
Each native check has a five-second timeout and a strict finite result schema.
Interruptions stop further reads; unexpected errors are redacted.

The executable is copied from the same verified byte buffer into a new
effective-user-owned mode0700 workspace directory and exclusive mode0500 file.
Descriptor-only Darwin ACL checks refuse inherited/explicit grants. A held
directory becomes CWD only during process creation, so source-path or ancestor
replacement cannot redirect execution. The parent CWD is restored; cleanup
checks owned file/directory identities and never recursively deletes anything.
Only our original executable enters this scratch directory, not policy data.
In the root live run the private copy is root-owned. No host file or setting
outside the project is written. macOS refused direct `/dev/fd` Mach-O execution
in an inert own-code control, so descriptor-path execution is not assumed.

`schema.py` is a pure scanner. It reports every observed fixed catalog field,
presence/count and overlapping scalar predicates, with separate derived
expression and malformed-row counters. Unknown names remain aggregate counts.
Generic Image4 catalog completeness is not claimed; the narrower formatter
catalog is qualified by the pinned REA/LLVM evidence. `CPRO` TEXT and `CRPO`
JSON stay distinct. Zero-valued subcounts are implicit in the compact output;
all observed fields and a fixed unseen-catalog list remain available.

JSON must be one complete document. Failures now name a fixed UTF8, envelope,
syntax, duplicate, depth or node stage. No arbitrary prefix extraction occurs.
Successful JSON capture is separate from successful JSON parsing.

`both_proposed_parsers_accepted` means only that both private desktop captures
satisfy the proposed C syntax/semantic parser. It does not establish paired
Recovery, final security admission, selected boot-object identity, installation,
native entry, SMP or performance. `native_ready`, `admission_verified` and
`Recovery_parser_installed` remain false. No mount, Startup Disk, security,
firmware, boot-object, stage or install command exists here.
