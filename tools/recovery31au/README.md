# 31AU: new diagnostic transaction package

This original adapter prepares a **new** controller, profile, workspace kit and
one-paste Recovery pages. It preserves the spent 31AR state and all old kits.
Preparation does not install a boot object or make another native window ready.

The new controller records finite selected-object read/framing/codec/decoded
identity categories before rollback, while the unchanged original recognizer
remains the sole identity authority. Candidate CTRR and exact selected-object
guards remain separate requirements. The prior saved candidate was UNKNOWN with
explicitly disabled Kernel CTRR. This package does not reinterpret that record
as a successful installation or firmware rejection.

## Reused source and new names

The source closure retains every one of the 167 frozen 31AS inputs, including
the original native reader, renderer, stager, HTTP parser and AS bootstrap repair.
It adds the six original 31AT diagnostic adapter files, the new 31AU controller,
this packaging code, public build/profile/delivery records and M1 instructions.
All old sources are checked by exact SHA-256 before their code is loaded.

The profile validator derives from the unchanged original MIT validator with
one verified initial-payload substitution and two finite schema/name selectors.
Initial admission now requires exact BOOT021 after the confirmed rollback; it
does not reuse the old 31AF-only baseline or any old comparison key.
The renderer changes only the namespace/helper selectors and uses the complete
AS checked hash-producer/profile-size/SHA/preflight repair. Each source
transformation verifies an exact reversal. A source mutation refuses.

The candidate remains the same 153,190,400-byte matched RAM diagnostic and exact
boot021 remains 3,932,160 bytes. This is not an accelerated Omarchy desktop build.
The public profile pins both and the newly built helper. The independent restore
block has no candidate-file dependency. Every result keeps default/restart claims
separate; neither the renderer nor the controller restarts a Mac.

## Offline workspace preparation

After the exact new production helper and public pin records are reviewed:

```sh
python3 -I tools/recovery31au/package.py --assemble \
  --helper build/boot-object31au-native/production-v2/ilinux31au-reader \
  --candidate build/ilinux-31ar-kit/candidate.macho \
  --rollback build/ilinux-31ar-kit/m1n1-boot021.bin \
  --output build/ilinux-31au-kit-v2

python3 -I tools/recovery31au/package.py --prepare \
  --kit build/ilinux-31au-kit-v2 --output build/31au-page-production-v2

python3 -I tools/recovery31au/package.py \
  --page build/31au-page-production-v2/recovery.html --check-only
```

All outputs must be absent, real paths beneath the checkout's ignored `build/`.
Assembly copies only exact own project artifacts using held, rechecked input
descriptors. Preparation never constructs a host metadata backend or controller.
`--prepare-source-page --output build/31au-source-page-v2` renders the same public
page without requiring private binary transfer, and records delivery unverified.
No controller, mount, policy or boot action runs in either preparation mode.

Default and `--help` are inert. Invalid operation/option combinations refuse.
Source, profile, build, delivery and exact page bytes are rechecked before output
success. The HTML contains complete install and independent restore boxes, plus
separate one-box pages. Copy the desired whole box, quit the browser, then paste
once into Recovery Terminal. No simultaneous-window or clipboard exercise exists.

## Later explicitly authorized operations

`--stage --kit build/ilinux-31au-kit-v2` is a separate **lab Data copy**, not a boot
installation. It reuses the full frozen stager with only the helper-mode/name,
destination, state/profile/inventory selectors changed. Fresh exact hardware,
System/Data/Original/APFS role checks, root-owned state parent and descriptor ACL
checks, state/kit absence, held-FD hashes, durable private copies and final
metadata rechecks remain. Existing destination/state causes refusal. No old state
is reset, removed or overwritten. No Preboot mount or policy command runs.

`--page ... --bind PRIVATE_IPV4 --port PORT --seconds SECONDS` is a separate
bounded page service, at most 1,800 seconds. It reuses the unchanged HTTP parser
and address restrictions, serving only reviewed in-memory HTML at `/` or `/31au`.
No directory listing, file transfer, upload, control API or access log exists.
Private URL/process metadata stays out of Git. The M1 operator can manage serving;
offline review does not require another live-server or clipboard calibration loop.

An actual installation/diagnostic/rollback visit requires the later concrete
authorization and M5 cue. Keep recording off during Recovery authentication.
Never boot after a refusal; preserve the new finite diagnostic record and use
the independently guarded restore under its approved scope. Do not replay the
old 31AR transaction or infer exact installation from Apple exit zero.
