## Review findings fixed before hardware use

The first integration used an obsolete tracker method name; the independent
review caught it before execution. The final adapter uses the bounded tracker,
preserves partial counts on interruption, and refuses any latched error.

The frozen startup RPC temporarily set a global exception guard while CPU1
could begin executing. The new original helper issues the same two approved
32-bit stores without touching that guard. It has a fixed return marker,
allowlisted addresses/value, DSB and the verified proxy epilogue. Neither an
extra power operation nor a protection change was added.

Source review also corrected a proposed shareability check: m1n1's mapping
uses Outer Shareable, not the Linux mapping's Inner Shareable observation.
EL2 probes use the actual VHE regime; unrelated read-as-zero HCR bits do not
cause unnecessary refusal. No protection bit is changed to pass a check.

A host interruption test initially expected the tracker to lose its observed
phase. The implementation correctly retained phase 3; the assertion was corrected
and the full host/VM runs passed. The final VM job passed on its first run.

## What the next boot can establish

A refusal before startup may locate a mapping/permission/publication problem.
A visible early record can identify whether CPU1 reached the recorder, its
incoming EL and selected SCTLR M/C/I bits. Later reset/spin records locate
additional progress. Verified arrival permits repeated callbacks/counter checks
and a final idle-loop state check within the same attempt.

A zero record still cannot distinguish absent execution from an early fault or
invisible store. AT/readback establish CPU0 observations; they do not prove CPU1
instruction visibility, incoming mappings or cache coherence. A complete phase 3
record does not prove the final barrier or replay returned. The ordinary C stack
is unchanged; the alternative Device-memory stack stays held.

Timer round trips include USB/software/journal overhead. This is neither a
CPU-frequency benchmark nor a Linux SMP/interrupt/coherence/energy test. No Linux
handoff from this diagnostic, additional core, storage initialization, new boot
object, firmware, security or volume operation is included. No fresh REA query
was necessary to implement this adapter: public bootloader source and exact
image/assembly checks answer its concrete software questions; the earlier
bounded REA findings remain available without inventing another power write.
