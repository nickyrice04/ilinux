# Matched J716c community kernel, offline build

This job builds Cameron Cooper's published M5 Max/J716c kernel instead of
reimplementing its hardware support. It does not boot the produced kernel,
change a boot object or policy, install host software, or qualify native
performance. The matching Aura/Mesa build is job 097.

## Inputs and trust

`inputs.json` pins all 21 input files (487,044,788 bytes total), their exact
sizes, SHA-256 digests and original URLs. The kernel source is commit
`a59e709c737777495c84541c6afb6c862bb79227`; its complete archive reconstructs
Git tree `5960d8ab03fef0f87e91e84fe1a8d969173da8de`. The data-only
`source_archive.py` computes all Git blob/tree objects, including executable
modes, symlinks and case-distinct filenames, without executing or extracting
source on macOS. The verified tree contains 98,476 files and 125 symlinks.

The full 10,123-option reference configuration has SHA-256
`3c11e751cb6d6e0358429230d28121c7f383aa5437a2e0b7d181b85f6dd7dbe8`.
It comes from the publisher's pinned
[bring-up documentation](https://github.com/cameroncooper/linux/tree/5e11068a1c6d8fccb155bc6e0159cc16107e53ec/Documentation/arch/arm64/apple-j716c-bringup).
The source tree is unchanged; no device-tree or driver patch is applied.

The guest extracts versioned ALARM LLVM/lld 22.1.8 and bindgen 0.73.2 packages,
and official Rust 1.96.1 components into a fresh RAM directory. Before any
package extraction, GPG verifies every package's detached signature using a
copy of the guest's existing public ALARM keyring and full/ultimate trust.
The exact signing and primary keys must be current, unique and usable; actual
expired, revoked, disabled or ambiguous keys and weak signature digests refuse.
Unrelated `KEYEXPIRED` messages emitted while GPG rebuilds the complete copied
trust database do not override a separately checked, current actual signer.
No trust, expiry, clock or weak-digest override is used.

Rust's signed release manifest is checked against the pinned official Rust
release key `108F66205EAEB0AAA8DD5E1C85AB96E6FA1BE5FE`. This is an explicit
pinned-key authority, distinct from existing ALARM keyring trust. All component
hashes agree with that manifest. No package or Rust installer script runs,
and neither global keyring is changed.

The bindgen executable matches version 0.73.2 but has SHA-256
`898c2a5364f33b7f8c495de4ad499e8eacdee234f021ff94a5348afdd7700c77`,
which differs from the publisher's recorded binary. This is a version-matched
reproduction, not a claim that all toolchain binaries or kernel output are
byte-identical to the publisher's.

## Case-sensitive build and complete configuration check

The existing macOS workspace share is case-insensitive. Linux source, tools,
objects and installed modules therefore live in a verified case-sensitive
32 GiB guest tmpfs. In particular, module paths such as `xt_DSCP` and `xt_dscp`
must never be copied as an unpacked tree to the host. The guest exports the
module tree as an archive instead.

The retained ARM64 VM uses 48 GiB memory, eight vCPUs and six make jobs, with
no network interface except loopback and no new disk. Both projects' `quiet`
and `vm` locks are held for the whole VM run. The existing guest root disk and
boot kernel are reused; no packages are installed. The job compares the
package list before and after its work.

The published build identity is retained: `SOURCE_DATE_EPOCH=1794338095`,
`KBUILD_BUILD_USER=j716c`, `KBUILD_BUILD_HOST=bringup`,
`KBUILD_BUILD_VERSION=1`, `ARCH=arm64`, `LLVM=1`, and empty command-line
`LOCALVERSION`. The entire reference configuration is passed through
`olddefconfig`, and every resulting option is compared.

Only two exact metadata differences are qualified:

* `CONFIG_CC_CAN_LINK`: absent to `y`, from the compiler's successful user
  link probe.
* `CONFIG_PAHOLE_VERSION`: 131 to 132, only while `DEBUG_INFO_NONE=y` and all
  DWARF/BTF debug generation remains disabled.

Both values are generated by the pinned source's
[`init/Kconfig`](https://github.com/cameroncooper/linux/blob/a59e709c737777495c84541c6afb6c862bb79227/init/Kconfig).
Any other difference refuses. The resolved configuration's SHA-256 is
`c674ec637dcc1bae70cfb5e0d2fb8ab4ec2f4a331776c983e07de68791389acd`.
It is semantically matched under these two explicit exceptions, not
byte-identical to the published file.

## Running the job

Inputs belong in a new ignored workspace directory. Download each file from
its manifest URL, verify its exact size and SHA-256, and save a byte-identical
copy of `inputs.json` as `manifest.json` there. Do not execute third-party
input files on the host. This job requires the project's already provisioned
ARM64 VM, existing keyring and explicit exclusive build-window coordination.

The source archive can be verified as data on either OS:

```sh
python3 -I virtualization/jobs/096-j716c-community-kernel/source_archive.py \
  build/j716c-community-kernel/inputs/linux-a59e709c7377.tar.gz
```

After the exclusive VM window is authorized, run from the repository root:

```sh
python3 -I virtualization/jobs/096-j716c-community-kernel/build-host.py \
  --approved-build-window \
  --inputs "$PWD/build/j716c-community-kernel/inputs" \
  --output "$PWD/build/j716c-community-kernel/build-new"
```

The output directory must be fresh. The host wrapper takes a recipe snapshot,
verifies it stayed unchanged, and requires guest-job exit zero and the artifact
validator's `PASS`; VM shutdown alone is insufficient. The VM's retained runner
can wait about 60 seconds for network discovery before starting the no-network
job.

Original host-side unit controls:

```sh
python3 -I -m unittest discover \
  -s virtualization/jobs/096-j716c-community-kernel -p 'test_*.py' -v
```

These tests process original synthetic fixtures and source metadata only.
Third-party tools, build scripts and kernel compilation execute only in the VM.

## Artifacts and remaining gates

The job builds `Image.gz`, all configured modules, and
`apple/t6050-j716c.dtb`. It validates the ARM64 Image magic and 16 KiB page flag,
compressed/uncompressed equality, expected release, all modules' AArch64 ELF
headers and vermagic, archived module count, full configuration and static
18-core topology. `static_128MiB_fit` is only a file/header size check.

The upstream device tree contains foreign per-unit data. Its exported filename
is `t6050-j716c.PRIVATE.dtb`; it and `modules.PRIVATE.tar.gz` stay in ignored
workspace output and must not be publicly copied or deployed as-is. Runtime
ADT values, release addresses, memory/framebuffer mappings and executable
windows require matching target handling. The complete matching firmware,
Aura Stage1/Stage2, graphics userspace, guardian, per-device inputs and package
safety gates remain separate requirements.

A successful build establishes source/config/toolchain reproducibility and
static artifact consistency. It does not establish native boot, all-core
startup, GPU behavior, frequency/thermal policy, suspend, or macOS-level
performance. No restart is authorized or prepared by this job.

## Producer result, November 16

The real full build passed in 548 seconds inside the isolated VM. It produced
`7.3.0-j716c-bringup-unified`, a 16,764,671-byte `Image.gz`, 1,749 verified
AArch64 modules and the static 18-core J716c device tree. VM exit, guest job exit,
artifact validation, source bindings and unchanged package sets all passed.
The kernel's compressed SHA-256 is
`9885e0154605ba37ff35c6415888dc7f7484c8de1a9f13c6fed2684aad0eed7e`;
it differs from the publisher's tested binary.

All 30 original unit methods pass with zero skips. After the build, host and
guest preflight gained an explicit exact comparison with the recipe's own
`inputs.json`, with five new refusal/identity controls. The actual producer's
manifest was already byte-identical; no compiler, source or option changed.
`validation.json` separately retains the historical v4 recipe hashes and this
later preflight-only change. No repeated build is represented by that change.
Native boot, SMP operation and performance remain NOT RUN.
